# 4차 요구사항 정의서

_SKN35 4차 1팀 · Docentalk (근거 기반 AI 미술관 도슨트) · v1.0 · 2026-11-04_

## 1. 개요

| 항목 | 내용 |
|---|---|
| 프로젝트 | Docentalk — 검증된 미술 문서만 근거로 답하는 AI 미술관 도슨트 웹 서비스 |
| 과제 주제 | LLM을 연동한 내외부 문서 기반 질의응답 웹페이지 개발 |
| 배경 | 생성형 AI는 미술 작품에 대해 그럴듯하지만 틀린 정보를 말하기 쉽다. 수집·검수한 문서 안에서만 답하고, 근거를 보여 주고, 근거가 없으면 거절하는 도슨트가 필요하다. |
| 4차 범위 | 3차 기능을 그대로 유지하면서 ① 백엔드를 Django로 이전 ② 답변 흐름을 LangGraph로 통합 ③ 하이브리드 검색으로 검색 정확도 개선 ④ AWS 클라우드에 직접 배포·CI 구축 |
| 내외부 문서 | **외부**: 미술관·백과사전 등에서 수집한 공개 문서(작품 해설·작가 생애·작가 비교)<br>**내부**: 팀이 검수해 작성한 보정문·보강문(`data/mappings/document_corrections.json`, `document_supplements.json`). 답변 시 보정문을 우선한다. |
| 데이터 규모 | 작가 10명 · 작품 277점 · 문서 426건 · 청크 1,775개 |
| 관련 문서 | [01 테스트 결과서](01_테스트결과.md) · [02 시스템 구성도](02_시스템구성도.md) · [03 화면설계서](03_화면설계서.md) · [decisions.md](decisions.md) |

## 4. 제약사항

| 제약 | 내용 |
|---|---|
| 기술 (과제 요구) | 백엔드 Django, LLM 연동, 클라우드 배포 |
| 일정 | 2026-11-04 하루 개발 → 11/05 오전 최종 점검. 범위를 3차 피드백 반영과 구조 이전으로 한정 |
| DB | 작품 벡터를 `VECTOR(1536)`로 저장하므로 벡터 검색이 되는 TiDB Cloud를 유지 (RDS MySQL은 벡터 검색 미지원) |
| 화면 | 3차 Flutter Web 화면 유지. 빌드 결과물(HTML·CSS·JS)을 nginx가 서빙 |
| 주소 | 도메인을 구입하지 않아 IP(`http://13.125.176.74`)로 서비스, HTTPS 미적용 |
| 데이터 | 수집한 작가 10명의 문서 범위 안에서만 답변. 다른 작가·일반 상식 질문은 거절 |
