LangGraph 적용 테스트 결과

SKN35 4차 1팀 · 로컬 환경 · 2026-11-04
결론: 도슨트 답변 흐름을 LangGraph 그래프 하나로 바꾼 뒤에도 품질은 3차와 같은 수준이에요.
  • 같은 날 같은 데이터로 돌린 45문항 평가: 3차 원래 코드 41/45(91.1%) → 4차 LangGraph 42/45(93.3%). 둘 다 목표 90%를 통과했어요.
  • LLM 생성 단계를 기록하는 39문항 비교: 자동 검사 결과와 검색된 청크가 39/39 모두 같았어요.
  • 실패 문항은 모두 3차 때부터 있던 refused 상태값 문제와 과잉 거절이에요. 같은 코드에서도 실행할 때마다 달라지는 경계 문항이에요.
  • 청크 검색 점수(Recall@5 0.787)는 그대로 목표에 못 미쳐요. LangGraph는 검색 방식을 바꾸지 않았으니 예상한 결과예요. 하이브리드 검색으로 해결할 항목이에요.

1. 무엇을 바꿨나

3차에서는 같은 답변 흐름이 두 곳에 따로 있었어요. 일반 답변(service.answer)과 스트리밍(stream.answer_events)이 분류·범위 판정·검색·생성·검증을 각각 했어요. 4차에서는 이 흐름을 backend/llm/docent/graph.py의 그래프 하나로 합쳤고, 두 경로가 같은 그래프를 실행해요.

classify ─(거절·단답)→ 끝
   └→ scope ─(범위 밖)→ 끝
        ├→ recommend → 끝
        └→ retrieve ─(자료 없음)→ 끝
             └→ generate → validate → 끝
  • 스트리밍은 생성 노드가 LangGraph custom stream으로 토큰을 내보내는 방식이에요.
  • 프롬프트(docent-grounded-1.5.1), 검색기, 검증 규칙, 모델(gpt-4.1-mini, temperature 0.3)은 바꾸지 않았어요. 그래서 이번 테스트의 목적은 "흐름 구조만 바뀌고 결과는 그대로인가"를 확인하는 거예요.
